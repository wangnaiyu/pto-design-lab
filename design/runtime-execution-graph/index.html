Runtime Execution Graph PRD

版本：V1.0 状态：产品方案 需求日期：2026-07-20 结构化日期：2026-07-23

1. 背景与目标

PyPTO 开启 dependency generation 后会在 JIT 输出中生成 dfx_outputs/deps.json。当前用户需额外运行 simpler_setup.tools.deps_viewer 并打开 HTML；目标是在 pypto-toolkit IDE 插件内直接完成解析、构图、传递约简和交互展示。

成功结果：

  • 无需 Python、Graphviz 或预生成 HTML。
  • Full / Reduced / Omitted、节点标记与 simpler viewer 语义一致。
  • 本地处理，不依赖外部网络。
  • 缺少 name map 或性能 sidecar 时仍可降级展示结构图。

非目标：

  • 不采集或修改 runtime 数据。
  • 不把 dependency graph 当作时间线。
  • 🔥 不表示性能热点，⭐ 不表示真实关键路径。

2. 用户入口

P0 支持：

  1. 文件树右键 deps.json → Open Dependency Graph。
  2. 打开 deps.json 时在编辑器标题栏显示入口。
  3. JIT 输出列表对包含 dfx_outputs/deps.json 的运行显示入口。
  4. 命令面板提供 PyPTO: Open Dependency Graph。

展示载体为 IDE Webview 或原生图面板。

3. 输入与数据契约

必选输入为 deps.json，核心集合为 tasks[]、tensors[]、edges[]。可选输入为 name_map_*.json 和 l2_swimlane_records.json。

name map 优先级：

  1. 用户显式选择；
  2. 同目录修改时间最新；
  3. 回退到 func_id。

task_id、pred、succ、tensor_id、buffer_addr 必须保留为原始字符串或无符号 64 位值，不得直接转为 JavaScript Number。Task ID 拆分仅使用 BigInt。Task ID 必须按输入声明的 runtime 及格式版本解析，缺失或未知 runtime 时不得猜测布局。

固定实现 runtime@31f9e72e 中，TMR（tensormap_and_ringbuffer）使用 (ring_id << 32) | local_id：ring 左移 32 位，但有效位宽为 8，local 为 32 位。HBG（host_build_graph）使用 space / parent / local 布局，没有同一 ring 语义。raw_halves 在 bit 32 拆分原始高低半部，不代表 32 位 ring。

以下仅示意已校验的 TMR 值；超出 8 位 ring 范围或属于无效哨兵的值应拒绝，不得靠掩码静默截断：

ring_id  = (task_id >> 32) & 0xff
local_id = task_id & 0xffffffff

4. 图构建规则

  • 节点集合是 tasks[].task_id、所有 edges[].pred/succ 和可选性能数据 task ID 的并集。
  • edges=[] 时仍显示 tasks[] 中的孤立节点。
  • 结构边按唯一 (pred, succ) 去重，用于绘图、fanin/fanout 和传递约简。
  • 原始 edge 作为注释边保留 tensor、arg、source、overlap 等详情。
  • 同一任务对有多条注释边时，默认只画一条结构箭头。
  • 对声明为 TMR 的输入，全部节点都在 ring 0 时显示 local_id；只要存在非零 ring，统一显示 (ring_id, local_id)。HBG 输入使用其声明的 space / parent / local 标签。

5. 节点与标签

类型 判定 编码
AIC 仅 AIC kernel 有效 蓝色圆角矩形
AIV 仅 AIV kernel 有效 橙色椭圆
MIX AIC 与 AIV 同时有效 绿色菱形
alloc 分配任务 灰色虚线 note
dummy 有 task、无有效 kernel 灰色普通节点
unknown 无法识别 浅灰圆角矩形

kernel_ids 按 [aic, aiv0, aiv1] 解析，-1 表示无效。存在 L2 sidecar 时合并同一 task_id 的记录，否则回退到 kernel_ids。

标签格式：

<marker> <task-id> · <func-name> ↓<fanin> ↑<fanout>

函数名回退顺序：name map → L2 记录 → f<func_id> → alloc/dummy/unknown。

6. 标记与邻接语义

🔥：early_dispatch=true 或节点为 alloc，表示 speculative early-dispatch 的直接生产者。

⭐：节点有直接前驱；全部直接前驱都有 🔥；且至少一个直接前驱不是 alloc。它只表示结构候选，不证明运行时实际提前调度。

↓N 和 ↑M 分别表示不同的直接前驱和直接后继数量。所有标记与计数均基于完整唯一结构图，不随显示模式改变。

7. 边模式与布局

模式 可见边
Full 全部唯一结构边
Reduced 按声明算法约简后的边集；采用 tensor lifetime 保护时不承诺全图最小
Omitted 被传递约简移除的冗余边

三个模式复用完整图的一套节点布局，切换时节点不得跳动；只更新可见边数。若检测到环，禁用 Reduced / Omitted 并明确提示传递约简不可用。

8. SPMD、交互与详情

  • block_num > 1：红框、红色 xN，Hover 展示 block number。
  • 空白拖拽平移；滚轮以指针为中心缩放。
  • 点击节点打开详情；点击空白或 Esc 关闭。
  • F 适配窗口，R 恢复 1:1。
  • 详情展示 predecessor / successor，并按 name_hint 分组；先按数量降序，再按名称升序。

详情数量是不同相邻任务数，不是 tensor、annotated edge 或路径数。

9. Tensor 详情模式

“Show Tensor Info”开启后显示 INPUT / INOUT / OUTPUT / OUTPUT_EXISTING 端口与参数信息，包括 arg index/type、tensor label、dtype、storage、buffer numel、shape、strides、start offset。

  • INOUT 同时出现在输入和输出区。
  • tensor 名按 tensors[] 顺序生成 T0、T1……
  • source=explicit 用虚线。
  • overlap != covered 时提示真实 overlap 状态。
  • 无法确定 arg slot 时连节点主体，不猜测端口。

10. 状态、错误与性能

状态栏显示节点数、当前可见结构边数、模式、文件名及可选 sidecar 加载状态；图例必须解释节点类型、SPMD、fanin/fanout、🔥、⭐。

JSON 错误、缺字段、无法解析的 pred/succ、sidecar 读取失败、空图和环均需给用户可理解的通知。可降级情况继续展示可用内容并报告跳过数量。

P0：本方案验收规模下平移、缩放、选中和模式切换无明显卡顿，切换模式不得重算布局。P1：千节点策略、后台布局、进度/取消及按 ID、函数名、标记、core type 搜索。

11. P0 验收

  • 本方案的构造验收基准：构造验收集 Full 为 516 节点 / 1032 边，Omitted 为 516 节点 / 4 边。
  • 三种模式节点位置一致；Omitted 中 fanin/fanout 与 Full 一致。
  • (1, 3) · projection_head 显示 🔥⭐ (1, 3) · projection_head ↓2 ↑16，详情包含 alloc ×1、normalization_stage ×1、selection_stage ×16。
  • 只有 alloc 前驱的节点不显示 ⭐；任一直接前驱无 🔥 时也不显示。
  • block_num=16 显示红框和 x16。
  • 超过 JS 安全整数范围的 ID 无精度丢失。
  • 缺 sidecar 可打开；孤立节点可见。
  • A→B→C 加 A→C 的测试图在三个模式中分别显示 3 / 2 / 1 条边。
  • 有环时 reduction 被禁用并显示警告。

注：构造验收集输入 deps.json 统计为 512 个 task；516 是 viewer 节点并集的验收数，可能包含只出现在边或可选性能数据中的 task，二者不可混写。
