一句话概览02

把 toolkit 的“图与数据”接进用户已有的 agent，而不是再造一个聊天框

问题

用户同时用 pypto GUI 和 terminal 里的 Claude/Codex；两者是两个进程，agent 看不见你在泳道图上框了什么，只能靠文字复述。

方案

插件拉起一个本地 MCP 网关，持有实时 GUI 状态；任何 agent 连同一个网关，就地触发 18 个候选 pypto skill，结论回投三视图。

价值

诊断—建议—验证形成闭环：设计/开发/调试/调优四类活动都在“数据所在处”完成，经验可沉淀、可复现。

🎯 设计· ⌨ 开发· 🩺 调试· ⚡ 调优· 📌 沉淀
本方案对三种主力 agent 情况都成立：Claude Code / Codex / 未装 agent（插件自带 runtime 兜底）。

MCP 把 A 与 B 解耦
字节在云上或插件里都行；只要用一个本地 MCP server 暴露能力，Claude 与 Codex 看到的都是“一个 MCP server”，不关心字节在哪
反之：只用“往工程塞 SKILL.md”，存放位置就被死绑定，且宿主是否消费取决于其 Skills 发现机制，不能按宿主名称排他判断。
概念答疑 ②08

存放模型：包管理器的 lockfile 心智，而非二选一

① 工程内 model-workspace/

  • .pypto/skills.lock · 钉版本[进git]
  • .pypto/config.json · 网关/边界
  • .pypto/skills/ · 团队覆盖(可选)
  • .mcp.json / AGENTS.md · 发现薄壳
  • .pypto/cache/·output/ [gitignore]

② 本机磁盘（工程外）

  • ~/.vscode/…/pypto-toolkit/skills/
  • 受管 skill 核心 · 随插件 · 离线
  • 网关进程 · 长驻 · 持有实时状态

③ 组织内网（远端 · 可选）

  • registry 镜像 · 集中更新
  • 气隙企业镜像于内网
  • 基础功能不依赖它
类比 node_modules/~/.cargo = 本机 bundle Cargo.lock = 工程 pin 私有 npm registry = 内网镜像 → 仲裁：工程覆盖 > bundle > 镜像
同时拿到：可复现（lock 进 git）· 可离线 · 可定制 · 不漂移 · IP 可控。符合 share-safe。
概念答疑 ③ · 核心09

能力网关 = 两个进程之间的“共享内存 + 翻译官”

✗ 错误做法

每个 agent 各自 stdio 拉起一个 server 子进程 —— 子进程互相独立，都看不到 GUI 状态。

✓ 正确做法

扩展进程跑唯一一个长驻 server，绑定本机 endpoint，持有权威实时状态；各 agent 连的是转发到它的薄适配器。

Claude CodeCodexVS Code Copilot自带 runtime
↓ 薄适配器（stdio↔socket / HTTP·SSE） ↓
PyPTO 能力网关 · 本地 MCP Server（扩展进程内长驻）
持有同一份实时 GUI 状态 · 能力由 pypto 实现，而非 VS Code
这正是“terminal 里的 agent 能看见你在泳道图上框的那一段”的物理实现。
※ 各 agent 具体配置文件位置与 VS Code MCP 发现 API 属设计意图，工程实现前按当时官方文档复核。

信息架构17

一个插件，一个侧边栏面板，四段递进

▸ Context（当前焦点）
agent 此刻“看到”的 Frame · Send / Pin / 清空 · staleness
▸ Skills（Palette）

▸ Runs（历史运行结果）
run 树 · 右键触发相关 skill · 回归/异常徽标
▸ Sessions & Playbooks
skill 运行史 · 可重跑 · extract 成 playbook

三条交叉引用是灵魂

  • Runs → Skills：run 是多数 skill 的数据入口
  • Skills → Runs：缺 run 时一键跳去 pypto-run
  • Context 贯穿：消除多视图焦点歧义
可发现性四层：Palette 主发现面 · 情境点亮 · 就地入口 · 首启引导。内嵌 skill 头号死因是“塞进去=藏起来”。

治理与边界19

既要好用，更要可信、可控、可落地

反模式 · 不能踩

  • 把所有问题塞回聊天框
  • 自动改主源码不留痕（默认写影子 worktree）
  • skill 名字 / 触发条件不可见
  • 过度 proactive 破坏心流（默认关）
  • 让用户文字复述视图能直接给的事

治理约束

  • 版本漂移：受管集中更新 + 工程只 pin
  • 数据边界：模型工程源码/权重不悄悄外发
  • 气隙内网：必须有 fully-local 模式
  • 权限模型：跑编译/profile/写 scratch 需授权
  • 长任务：profile 有进度 / 可取消 / 可后台
数据准备：保留格式契约，校验构造数据的身份、单位与关联。业务事实需 来源复核。
